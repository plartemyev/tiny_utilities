# archinstaller

> English: [README.md](README.md)

Настоящий документ содержит описание `archinstaller` — установщика Arch Linux,
функционирование которого осуществляется без участия оператора (unattended).
Программа `install` производит управление live-средой штатного установочного
ISO-образа Arch Linux по протоколу SSH — либо вновь созданной локальной
виртуальной машиной (далее — ВМ) VirtualBox/libvirt, охватывая весь цикл
от создания ВМ до перезагруженной системы, доступной по SSH. Программа
`workbook` формирует тот же порядок действий в виде пошагового
markdown-руководства с блоками команд, предназначенными для непосредственного
копирования. Выходные данные обеих программ формируются из единой модели
шагов (`archinstaller/steps.py`), вследствие чего руководство всегда
соответствует действиям, выполняемым программой `install`.

## Основные свойства готовой системы

- **Устойчивость загрузки к внешним воздействиям**: загрузка обеспечивается
  загрузчиком GRUB, зарегистрированным в NVRAM, а также неподписанным
  резервным загрузчиком `\EFI\BOOT\BOOTX64.EFI` — устаревшие загрузочные
  записи, изменённые идентификаторы дисков и сброс NVRAM в VirtualBox
  загрузке не препятствуют.
- **Доступ исключительно по ключам**: создаётся пользователь с правами sudo,
  не требующими ввода пароля; открытый ключ `--ssh-pubkey` заносится
  в `authorized_keys`; аутентификация по паролю в sshd отключается;
  на целевой машине генерируется новая пара ключей ed25519; пароли
  генерируются и выводятся в итоговой сводке.
- **Сформированные наборы пакетов**, отобранные на основе установочного
  ISO-образа Arch: базовый и консольный наборы, средства разработки
  (`--devel`), графическая среда Xlibre + Sonic DE с автоматическим входом
  в систему (`--graphical`; см. раздел *Графические установки*).
- **Надлежащая настройка TRIM**: по результатам опроса каждого диска
  включаются `fstrim.timer`, discard для файла подкачки и (для ВМ)
  непрерывный discard для корневой файловой системы; проброс на стороне
  гипервизора организуется автоматически (см. раздел *TRIM/discard*).
- **Экономное использование дискового пространства**: кэш pacman очищается
  после каждой транзакции; допускается его обслуживание кэширующим зеркалом
  локальной сети (`--local-mirror`), вследствие чего повторные установки
  удовлетворяются из кэша.
- **Автоматическое восстановление DNS**: используются DNS-серверы, полученные
  по DHCP, до тех пор, пока отвечает хотя бы один из них; при отказе всех
  серверов задействуются общедоступные резервные серверы systemd-resolved
  с автоматическим возвратом после восстановления сети.
- **Обоснованная базовая конфигурация**: NetworkManager + systemd-resolved;
  firewalld включается при каждой установке.
- **Настройка с учётом типа ВМ**: гостевые агенты в зависимости от
  гипервизора, исправление HDA для VirtualBox, параметры sysctl памяти,
  благоприятствующие работе virtio-balloon, привязка кнопки питания ACPI
  к корректному выключению машины, отключение блокировки экрана на рабочих
  столах ВМ (на физических машинах блокировка сохраняется).
- **Дополнительно устанавливаемый веб-сервер opencode** в виде пользовательской
  службы systemd с отдельно сгенерированным паролем и портом, открытым
  в firewalld.

## Сценарии применения

```bash
poetry install   # Python >= 3.13; для функционирования требуется paramiko

# новая локальная ВМ с графической средой на libvirt;
# пакеты — из кэширующего зеркала локальной сети
poetry run archinstaller install --provision libvirt --graphical --local-mirror

# существующая машина, загруженная с ISO-образа
# (в консоли ISO выполнить passwd; зафиксировать IP-адрес)
poetry run archinstaller install --target 192.168.1.50 --graphical

# переустановка ВМ VirtualBox с перезагрузкой средствами хоста
poetry run archinstaller install --target 192.168.1.51 --vbox-vm MyVM

# руководство для ручного выполнения вместо автоматизации
# (для включения создания ВМ добавить --provision)
poetry run archinstaller workbook --provision libvirt --graphical --local-mirror

# завершение послезагрузочного этапа прерванного запуска
poetry run archinstaller resume archinstaller-state-<hostname>.json
```

Параметр `--provision` обеспечивает создание ВМ с именем `--hostname`,
загрузку штатного ISO-образа и управление им через последовательный порт —
какая-либо подготовка целевой машины не требуется. Параметр `--local-mirror`
настраивает pacman на обращение к контейнеру `arch-cache-mirror` на данном
хосте (порт 8282) как при установке, так и в установленной системе: повторные
установки обслуживаются локальным кэшем без обращения к публичному зеркалу.

## Требования

- Загрузка UEFI; Secure Boot должен быть отключён (сборка GRUB не имеет
  подписи).
- `--disk` принимает обычное устройство вида `sdX`/`vdX`/`hdX`; именование
  NVMe не поддерживается.
- Резервное сканирование подсети /24 (см. раздел *Двухэтапное выполнение
  и восстановление*) охватывает 254 адреса; там, где оно нежелательно,
  следует использовать `--no-subnet-scan` (сканирование не выполняется
  при наличии промежуточного SSH-хоста либо не-IPv4 целевой машины).
- `--provision vbox`: VirtualBox на данном хосте (Extension Pack не обязателен;
  необходим для USB 3.0); `--provision libvirt`: `virsh` с доступом
  к `qemu:///system`.
- `--local-mirror`: контейнер `arch-cache-mirror`, доступный с целевой машины;
  доступность проверяется запросом `/healthz` до выполнения каких-либо
  необратимых действий.

## Порядок выполнения установки

1. Выполняется подключение к live-ISO от имени root (`--login-*`; допускается
   промежуточный SSH-хост; устаревшие записи `known_hosts` удаляются
   автоматически).
2. На целевой машине выполняются предварительные проверки: UEFI, определение
   гипервизора (`systemd-detect-virt`, либо фиксированное параметром
   `--virt`), опрос диска на предмет поддержки discard (либо `--discard`),
   проверка DNS с переходом на публичные резолверы при отказе, проверка
   работоспособности зеркала.
3. Сгенерированный сценарий загружается и выполняется: освобождаются
   оставшиеся от возможного предыдущего неудачного запуска монтирования
   и файл подкачки → выполняется разметка диска (раздел ESP объёмом 1 ГиБ
   и корневой раздел) → mkfs/монтирование → pacstrap → fstab → chroot:
   пароли, имя узла и локаль, GRUB (запись в NVRAM и резервная установка
   с `--removable`), initramfs, pacman.conf (Color, параллельная загрузка,
   набор IgnorePkg, multilib, репозитории `xlibre-stable` и `sonicde`
   с локально подписанными ключами), хук очистки кэша, sudo, файл подкачки,
   наборы пакетов, пользователь, ключ, усиление защиты sshd, сетевые службы,
   настройка TRIM, настройка ВМ, firewalld и конфигурация графической среды
   при её включении.
4. Производится перезагрузка: из гостевой системы либо средствами хоста —
   `--vbox-vm` (выключение питания, резервное копирование NVRAM, размещение
   диска в порядке загрузки перед DVD, запуск) либо установка с созданием ВМ
   (остановка ВМ, извлечение ISO-образа, загрузка с диска).
5. Второй этап выполняется по SSH с аутентификацией закрытым ключом,
   соответствующим `--ssh-pubkey` (при передаче ключа в виде строки
   используется откат к ключам агента и ключам по умолчанию): ожидание
   целевой машины (с резервным поиском по подсети /24 по имени узла),
   заглушка `resolv.conf` и восстановление DNS, часовой пояс, пара ключей
   пользователя, служба opencode, после чего выводится итоговая сводка;
   файл состояния удаляется.

Адаптация гостевой системы в зависимости от обнаруженного гипервизора:

| Цель | Адаптация |
|---|---|
| физическая машина | отсутствует |
| kvm / qemu | включается `qemu-guest-agent`; графические установки дополнительно включают демон SPICE-агента (у `spice-vdagentd.socket` отсутствует секция `[Install]`, вследствие чего применяется `systemctl add-wants`) и привязывают GPU к DRM-карте card0 (`initcall_blacklist=sysfb_init` в параметрах ядра), обеспечивая её обнаружение при перечислении DRM-карт в spice-vdagent и сопоставление экранов сервера с выходами X по PCI-адресу |
| oracle (VirtualBox) | `virtualbox-guest-utils` (графическая установка) либо `-nox` (консольная), включается `vboxservice`, фиксируется параметр HDA `position_fix=1` |
| vmware | `open-vm-tools` при графической установке |
| всё остальное | `hyperv` / `qemu-guest-agent` входят в базовый список, оставаясь неактивными |

Каждая целевая ВМ дополнительно получает `/etc/sysctl.d/90-small-cache.conf`
(`vm.watermark_scale_factor = 500`, `vm.vfs_cache_pressure = 20`): kswapd
активизируется раньше и вытесняет из памяти кэш страниц, а не кэши
dentry/inode, вследствие чего память остаётся доступной для возврата хосту
посредством virtio-balloon. Целевые ВМ VirtualBox дополнительно получают
`options snd-hda-intel position_fix=1`: DMA-буфер позиции эмулированной HDA
остаётся неизменным, вследствие чего при значении по умолчанию первое же
воспроизведение приводит звуковой граф в неработоспособное состояние
с бесконечным зацикливанием последнего фрагмента на хосте.

## Параметры командной строки

Параметры настройки системы, общие для `install` и `workbook`:

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--disk` | `/dev/vda` | подлежащий очистке диск; допускаются устройства вида `sdX`/`vdX`/`hdX`, а также NVMe-устройства вида `nvmeXnY` |
| `--hostname` | `arch-host-YYYY-MM-DD` | также используется в качестве имени создаваемой ВМ |
| `--username` | `nameless` | создаваемый пользователь (группы: video, scanner, optical, kvm, sys, wheel, uucp, games; +docker с `--devel`) |
| `--ssh-pubkey` | `~/.ssh/id_ed25519.pub` | ключ в виде строки либо путь к файлу; корректность проверяется |
| `--locale` | `en_US.UTF-8` | локаль |
| `--swap-size` | `16G` | размер файла подкачки `/swapfile` |
| `--timezone` | `Asia/Bangkok` | применяется после первой загрузки системы |
| `--root-password`, `--user-password` | генерируются, выводятся в итоговой сводке | учётные данные установленной системы |
| `--graphical` | отключён | графическая среда Xlibre + Sonic DE; см. раздел *Графические установки* |
| `--devel` | отключён | дополнить списками пакетов разработки (консольный набор — всегда; графический — также при наличии `--graphical`) |
| `--opencode` | отключён | выполнить развёртывание веб-службы opencode; см. раздел *Служба opencode* |
| `--local-mirror` | отключён | работа pacman через локальное кэширующее зеркало; см. раздел *Локальное кэширующее зеркало* |
| `--virt` | опрос | фиксированное значение `none\|kvm\|qemu\|oracle\|vmware\|microsoft` вместо автоматического определения |
| `--discard` | опрос (в режиме workbook — отключён) | принудительное включение TRIM/discard |

Параметры подключения (только `install`):

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--target HOST` | обязателен при отсутствии `--provision` | хост с запущенным live-ISO; совместно с `--provision` не допускается |
| `--target-port` | `22` | SSH-порт целевой машины |
| `--login-user` / `--login-password` | `root` / `local0instaLl` | учётные данные live-ISO; при использовании `--provision` пароль задаётся программой самостоятельно через последовательный порт |
| `--jump-host`, `--jump-port`, `--jump-user`, `--jump-password` | — | подключение SSH через промежуточный хост, аналогично `ssh -J`; при отсутствии пароль запрашивается |
| `--install-timeout` | `7200` | время (в секундах), предоставляемое на выполнение сценария установки |
| `--reboot-timeout` | `60` | время (в секундах) ожидания доступности SSH после перезагрузки |
| `--no-subnet-scan` | отключён | отключение резервного сканирования подсети /24 |
| `--vbox-vm NAME` | — | перезагрузка существующей ВМ VirtualBox средствами хоста (с установкой флагов discard на подключениях дисков); совместно с `--provision` не допускается |

Параметры создания ВМ (`install` и `workbook` с `--provision`):

| Параметр | По умолчанию | Описание |
|---|---|---|
| `--provision` | `none` | `vbox` либо `libvirt`: создание новой ВМ с именем `--hostname` с последующей установкой системы; совместно с `--target`, `--jump-*`, `--vbox-vm`, `--virt` не допускается |
| `--disk-size-gib` | `45` | размер создаваемого диска (ГиБ) |
| `--ram-gib` | `4` | память гостевой системы (ГиБ) |
| `--cores` | `4` | количество виртуальных процессоров (vCPU) гостевой системы |
| `--iso-path` | `~/Downloads/archlinux.iso` | должен указывать на существующий доступный для чтения файл `.iso`; штатный ISO-образ используется без изменений |

Применяются только с `workbook`: `--out PATH` (по умолчанию
`archinstaller-workbook-<hostname>.md`), `--with-passwords` и `--language ru`
(текст руководства на русском языке; по умолчанию `en`).

## Установки с созданием ВМ (`--provision vbox|libvirt`)

Состав оборудования, создаваемого для каждого из вариантов:

- **vbox**: UEFI; видео VMSVGA (256 МБ при `--graphical`, 16 МБ в консольном
  режиме); диск VDI на NVMe с включённым кэшем ввода-вывода хоста,
  подключаемый с `--nonrotational on --discard on`; две сети virtio-net —
  NAT (доступ в интернет; проброс SSH-порта
  `127.0.0.1:<порт>` → `10.0.2.15:22` сохраняется как резервный путь,
  свободные порты выбираются автоматически из диапазона 23950–24000) и
  host-only адаптер (быстрый канал хост↔гость: через него идут SSH-транспорт
  и локальное зеркало пакетов; адрес закрепляется статическим профилем
  NetworkManager, привязанным к MAC сетевой карты — DHCP-сервер host-only
  сети VirtualBox сопоставляет конфигурации по MAC с опцией client-id,
  которую NetworkManager отправляет, поэтому привязка на стороне сервера
  сама по себе не учитывается); последовательный порт в режиме TCP-сервера
  на стороне хоста; звук HDA с использованием аудиодрайвера хоста по
  умолчанию; аппаратные часы (RTC) в UTC; общий буфер обмена; USB 3.0 (xHCI)
  при наличии установленного Extension Pack. Host-only сеть (`vboxnet0` с её
  DHCP-сервером) при отсутствии создаётся автоматически.

  Разделение продиктовано пропускной способностью (iperf2, VBox 7.2.22):
  любой путь через NAT ограничен пользовательским NAT-движком
  (~200–800 Мбит/с), тогда как host-only мост пропускает 1,2–2,5 Гбит/с на
  той же virtio-карте (однопоточный SSH: ~300 → ~630 Мбит/с). NAT-адаптер
  остаётся маршрутом по умолчанию и единственным источником DNS — DHCP-сервер
  host-only сети не выдаёт ни того, ни другого, поэтому поведение при смене
  сетей не меняется.
- **libvirt** (`qemu:///system`): q35 + UEFI; процессор `host-passthrough`
  с `migratable='off'` и топологией, воспроизводящей SMT-структуру хоста;
  vCPU привязываются в соотношении 1:1 к старшим (вторым потокам) процессорам
  хоста, вследствие чего соседние vCPU одного гостевого ядра размещаются
  на одном физическом ядре (эмулятор закрепляется за непосредственно
  следующим целым ядром; при недостаточном числе ядер применяется общий
  cpuset); весь объём памяти выделяется сразу, с устройством virtio-balloon
  (`freePageReporting`, `autodeflate`); qcow2 на virtio
  с `discard='unmap' detect_zeroes='unmap'`; канал гостевого агента;
  сетевой адаптер virtio в первой пригодной сети (физический мост →
  `lan-routed` → NAT по умолчанию); звук ICH9 HD через бэкенд spice; spice
  с аппаратным GL при `--graphical` (в остальных случаях — локальный spice
  без GL); агентский канал spicevmc `com.redhat.spice.0` (транспорт
  spice-vdagent в гостевой системе: общий буфер обмена и подстройка
  разрешения под размер окна консоли); последовательный порт через TCP.

Порядок загрузки и установки: в меню systemd-boot загрузочного ISO-образа
программой выполняется «вслепую» нажатие клавиши `e`, дописывается
`console=ttyS0,115200`, после чего производится загрузка (нажатия клавиш
передаются приблизительно через 10 с после запуска ВМ; при упущенном окне
меню выполняется повторная попытка после перезапуска ВМ, всего 3 попытки).
В последовательной сессии выполняется вход от имени root, устанавливается
пароль root в live-среде (`--login-password`) и считывается DHCP-адрес
гостевой системы. Далее установка выполняется по SSH аналогично варианту
с `--target`, причём настройка discard включается всегда (оба варианта
создания ВМ изначально обеспечивают проброс TRIM). По завершении программа
выполняет заключительные действия со стороны хоста: остановку ВМ, извлечение
ISO-образа, загрузку с установленного диска — VirtualBox фиксирует созданные
гостевой системой EFI-записи в хранилище при выключении питания, NVRAM pflash
в libvirt сохраняется при destroy/start, вследствие чего установленный GRUB
в обоих случаях загружается непосредственно.

Совпадение имён (с существующей ВМ/доменом либо томом) является ошибкой —
следует указать иное `--hostname`. При недоступности перезагруженной системы
второй этап использует резервные механизмы в зависимости от гипервизора:
в libvirt аренда DHCP домена отыскивается по MAC-адресу; для VirtualBox
сначала выполняется повторная попытка через резервный проброс порта NAT
(NIC1), и лишь затем выводятся инструкции по восстановлению.

## Графические установки (`--graphical`)

Порядок установки пакетов имеет существенное значение: в первую очередь
устанавливается X-сервер Xlibre (`xlibre-xserver` содержит
`Provides: xorg-server`, вследствие чего зависимость sonic-login-manager
разрешается в сборку xlibre, а не в конфликтующий штатный пакет), затем
`sonicde-meta` (конфликтует со штатными пакетами KDE/Plasma и предоставляет
их замены, вследствие чего последующие зависимости разрешаются в замены
sonic), затем графический список пакетов.

Дополнительно настраиваются следующие компоненты:

- **sonic-login-manager** включается с автоматическим входом для созданного
  пользователя; сессия определяется автоматически по установленным
  `.desktop`-файлам (soniclogin не выполняет автоматический вход при
  отсутствии записи `Session=`).
- **Кнопка питания ACPI выполняет выключение машины**: в конфигурацию
  PowerDevil заносится действие Shutdown (для программных стеков, в которых
  обработка нажатий функционирует, например Wayland); на целевых ВМ демон
  полностью маскируется — обработка нажатий по X11 не работает, а его
  ингибитор в logind блокирует стандартное поведение logind, что делает
  кнопку неработоспособной, — вследствие чего срабатывает
  `HandlePowerKey=poweroff` в logind и `acpipowerbutton` со стороны хоста
  выполняет действие. Физические машины сохраняют как демон, так и обычную
  блокировку.
- **Целевые ВМ: блокировка экрана отключается** — отключаются автоматическая
  блокировка и блокировка при возврате из простоя, очищается сочетание
  клавиш Meta+L («Заблокировать сеанс»), чем исключается блокировка ВМ
  привычными действиями, адресованными ОС хоста.
- **Целевые ВМ VirtualBox**: вместо сборки `-nox` без графической части
  устанавливается полный `virtualbox-guest-utils` (интеграция
  с X11/Wayland).

## TRIM/discard

Возможность использования discard определяется опросом целевого диска
в live-среде (`discard_max_bytes > 0`; признак rotational приводится
исключительно для справки). При поддержке discard включаются `fstrim.timer`
(еженедельная пакетная очистка), опция `discard` в записи файла подкачки
fstab, а на целевых ВМ дополнительно корневая файловая система монтируется
с непрерывным `discard` (сохраняется genfstab), вследствие чего
освобождённые экстенты немедленно освобождают образ на стороне гипервизора.
При отсутствии поддержки никакие механизмы не включаются.

- `--discard` включает принудительно, без опроса; в режиме workbook по
  умолчанию отключено.
- `--vbox-vm` повторно подключает каждый подключённый жёсткий диск
  с `--discard on --nonrotational on` при выключенной ВМ — сжатие VDI
  в ответ на TRIM гостевой системы в VirtualBox выполняется только при
  наличии данных флагов. Флаги устанавливаются после опроса, вследствие чего
  гостевая система конфигурируется под discard независимо от результата
  опроса; неудачное переключение сопровождается лишь предупреждением
  (например, диски, подключённые к IDE-контроллеру, не обеспечивают проброс
  TRIM). Без `--vbox-vm` указанные флаги следует установить на подключении
  диска самостоятельно (настройки носителей ВМ).
- Создаваемые libvirt-домены получают
  `discard='unmap' detect_zeroes='unmap'`. Для самостоятельно создаваемых
  libvirt-доменов: virtio-blk объявляет поддержку discard изначально;
  актуальные версии программных стеков (libvirt ≥ 12.7.0 совместно
  с QEMU ≥ 11.1.1) обеспечивают проброс во всех режимах, если XML диска
  не отключает его посредством `discard='ignore'`; для устаревших версий
  требуется явное указание `<driver ... discard='unmap'/>`.
  `detect_zeroes='unmap'` дополнительно уплотняет записи с высоким
  содержанием нулей (например, новый mkfs при переустановке) в процессе
  работы. При появлении проброса повторных действий не требуется —
  включённая конфигурация гостевой системы приступает к освобождению
  блоков при следующем проходе.

## Локальное кэширующее зеркало пакетов (`--local-mirror`)

Контейнер `arch-cache-mirror`, размещённый на хосте, с которого запущена
настоящая программа (опубликованный порт 8282), используется в качестве
единственного источника пакетов pacman как для live-среды, так и для
установленной системы: mirrorlist заменяется единственной строкой
`Server = http://<mirror-host>:8282/$repo/os/$arch`, а дополнительные
репозитории переписываются на собственные сегменты зеркала
(`/xlibre/os/$arch`, `/sonicde/os/$arch` — pacman запрашивает базу данных,
именованную по секции pacman.conf, в связи с чем использование шаблона
`$repo` из mirrorlist для них невозможно). Ключи подписи по-прежнему
получают из исходных `.asc`-источников.

Для целевых ВМ в качестве хоста зеркала используется шлюз гостевой системы
по умолчанию (хост гипервизора, фиксированный для каждого варианта создания —
URL не зависит от смены сетей хоста), для физических машин — IPv4 основного
сетевого интерфейса хоста. Созданные VirtualBox-ВМ вместо этого используют
шлюз host-only сети (NIC2, `192.168.56.1` — сам хост по навсегда
фиксированному адресу): трафик зеркала идёт по быстрому host-only пути
вместо ограниченного NAT-движка. Этот путь входит через host-only интерфейс,
поэтому межсетевой экран хоста требует однократного исключения (до его
добавления программа задействует более медленный NAT-путь через LAN-адрес
хоста и выдаёт предупреждение); открытый порт заодно обслуживает физические
машины локальной сети, которые обращаются к тому же зеркалу по LAN-адресу
хоста:

```bash
firewall-cmd --permanent --add-port=8282/tcp
firewall-cmd --reload
```

Доступность проверяется запросом `/healthz` до
выполнения каких-либо необратимых действий; публичный резерв отсутствует,
в связи с чем отказ зеркала в процессе установки влечёт неудачу установки.

## Служба opencode (`--opencode`)

После первой загрузки выполняется включение `loginctl enable-linger` для
пользователя, устанавливается `~/.config/systemd/user/opencode.service`,
запускающий `opencode serve --hostname 0.0.0.0 --port 49374` с отдельно
сгенерированным `OPENCODE_SERVER_PASSWORD`; служба запускается
(`--no-block` с опросом `is-active`), порт открывается в firewalld.
opencode v2 защищает сервер базовой HTTP-аутентификацией с фиксированным
именем пользователя `opencode`; в итоговой сводке выводятся веб-адрес,
имя пользователя и пароль.

## Пошаговое руководство (`workbook`)

Формируется описание того же порядка установки — создание ВМ (опционально),
разметка диска, настройка в chroot, послезагрузочные действия — в виде
пронумерованных markdown-разделов с обоснованиями и блоками, предназначенными
для копирования; вспомогательная функция `retry` из сценария установки
раскрывается, вследствие чего каждый блок выполняется самостоятельно.
С `--language ru` текст руководства — заголовки, обоснования и примечания —
формируется на русском языке; команды остаются неизменными.

Руководство использует те же параметры настройки системы, что и `install`,
и не требует целевой машины: два факта, обычно получаемых опросом,
фиксируются параметрами (по умолчанию `--virt none`, discard отключён)
и проверяются формируемым шагом 0 «Сведения о целевой машине» — при
расхождении с машиной следует выполнить повторное формирование руководства
с соответствующими `--virt`/`--discard`. С `--provision vbox|libvirt`
руководство вместо этого выводит точные команды соответствующего варианта
создания и XML домена (данные хоста — свободные порты, каталог машины,
сеть libvirt — определяются в момент формирования), а также ручные замены
для автоматизированной загрузки и последовательной сессии.

Пароли выводятся в виде заполнителей `{{ROOT_PASSWORD}}`, что допускает
свободную передачу файла. Параметр `--with-passwords` обеспечивает подстановку
явных значений и генерацию отсутствующих: файл записывается с правами доступа
`0600`, снабжается предупреждением в начале, сгенерированные пароли выводятся
в стандартный поток вывода однократно — файл подлежит обращению как
секретный материал; пароли следует заменить при первой возможности.

## Двухэтапное выполнение и восстановление

Установка и послезагрузочная настройка выполняются в два этапа. Перед
перезагрузкой программа записывает файл `archinstaller-state-<hostname>.json`
(права доступа `0600` — файл содержит пароли) в рабочий каталог и удаляет его
по завершении второго этапа.

При отсутствии ответа перезагруженной целевой машины в течение
`--reboot-timeout` выполняется сканирование окружающей подсети /24
в поисках SSH-хоста, допускающего аутентификацию установочным ключом
и сообщающего заданное имя узла (отключается параметром `--no-subnet-scan`;
не выполняется при наличии промежуточного SSH-хоста либо не-IPv4 целевой
машины). При безрезультатности данного поиска выводятся шаги восстановления,
программа завершается с ненулевым кодом возврата с сохранением файла
состояния. После восстановления доступности машины (по любому адресу)
выполняется:

```bash
poetry run archinstaller resume archinstaller-state-<hostname>.json
```

Замечание относительно VirtualBox, относящееся к `--vbox-vm` (и установкам
с созданием ВМ): созданные гостевой системой загрузочные записи сохраняются
только при выключении питания — при перезагрузке из гостевой системы они
утрачиваются, а устаревший `BootOrder` приводит к невозможности выхода из
интерфейса прошивки. Перезагрузка средствами хоста позволяет резервному
загрузчику ESP выполнить загрузку установленной системы непосредственно:
выключение питания сохраняет NVRAM на диск (при `--vbox-vm` хранилище,
кроме того, резервируется для случая возврата к настройкам прошивки
по умолчанию, а диск размещается в порядке загрузки перед DVD).
